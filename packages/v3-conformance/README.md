# @simple-git/v3-conformance

A **transitional** oracle package. Its only job is to prove that the v4 rewrite is a
tooling/architecture change and **not** a behavioural or type-contract change, except for the
two sanctioned removals (see [`removals.json`](./removals.json)).

It lives in its own workspace package so its dependency tree (a frozen v3 baseline + the v3
integration suite run black-box) stays separate from the v4 source under refactor. Per the
plan it is **deleted once a few v4 minor releases confirm parity** — it is scaffolding, not a
permanent part of the public packages.

## What it guards

### 1. Type surface (active now)

`api-surface.golden.txt` is a normalised, order-independent snapshot of every symbol a consumer
sees from `import ... from 'simple-git'`, captured from the **v3 hand-written typings before any
v4 change**. It is generated by `scripts/api-surface.mjs` using only the TypeScript compiler API
(no extra toolchain to drift from).

- `pnpm --filter @simple-git/v3-conformance run api:check` regenerates the current surface and
  fails on any difference. This is the package's `test`.
- `pnpm --filter @simple-git/v3-conformance run api:surface` re-writes the golden — only run this
  for an **intentional** change, and record the reason in
  `docs/v4/TYPE-SAFETY-AND-TEST-INTEGRITY.md`.

Every diff must be reconciled against `removals.json` (the two sanctioned removals) and the
expected-delta log. A diff that is neither is an **unintended breaking change** and is a bug.

> Note: `typings-baseline/` is a verbatim, frozen copy of the v3 `.d.ts` files for human
> reference. Its `../src/*` re-exports intentionally do not resolve from this location — the
> machine golden is always generated from the canonical `simple-git/typings` entry, never from
> the copy.

### 2. Runtime behaviour (wired with the runner migration)

The strongest parity proof is the **v3 integration suite run unmodified, black-box, against the
built v4 `dist`** (resolved through the package `exports` map, not `src`). The integration tests
already only touch the public surface — they spawn real `git` via `newSimpleGit()` from
`@simple-git/test-utils` — so they are a true black box.

This is deliberately **not** attempted for the unit tests: those `vi.mock('child_process')` and
import from `src`, so they are white-box and are *ported* (not frozen). White-box parity is
covered instead by the API golden above, coverage, and assertion-count enforcement.

When the runner workstream lands, this package gains a `test:conformance` script that runs the
copied v3 integration specs against `simple-git`'s built artifact and is allowed to differ from
`main` only by the cases enumerated in `removals.json`.

## Removal criteria

Delete this package once:

1. the v4 public type surface is intentionally final (golden updated, deltas logged), and
2. the v3 integration suite has passed against `dist` across the agreed early v4 minors, and
3. the maintainer is satisfied parity is proven.
